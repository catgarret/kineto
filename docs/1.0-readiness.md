# 1.0 계약 준비도

1.0은 모듈 수가 아니라 공개 계약을 예측할 수 있는지로 판단합니다. 이 문서는 현재 자동 검증과 남은 외부 조건을 분리해 기록합니다.

## 동결 전 원칙

- 새 public API는 두 개 이상의 실제 사용 사례와 Vanilla Core 계약을 먼저 확보합니다.
- 어댑터가 Core와 다른 의미를 만들면 어댑터가 아니라 Core 계약을 수정합니다.
- 모든 계약 변경은 영문 changelog 뒤에 한국어 대응 항목을 추가하고, package·types·demo·docs를 함께 갱신합니다.
- 1.0 전에는 모듈 수를 늘리는 것보다 entry 비용, lifecycle, 접근성, browser evidence를 우선합니다.

현재 외부 게이트가 증거 없이 완료로 바뀌지 않도록 `npm run test:readiness-gates`가
실기기 QA 상태, 외부 사례 수, deprecated migration 조건, FLIP 확장 gate와
live-site parity monitor 연결을 함께 확인합니다. `npm run test:readiness-evidence`는
실제 증거 디렉터리의 날짜·환경·기대/실제 결과, case study의 필수 섹션·공개 동의,
deprecated fixture 조건과 브라우저 QA 이력의 커밋/CI 귀속을 별도로 검사합니다. 이 검사는 증거를 만들어내지 않으며,
실제 iPhone·Android 실행과 외부 사례 동의가 추가되면 해당 문서와 이력에 먼저 기록해야 합니다.

이번 내부·배포 완료 근거는 [제품·기술 로드맵](ROADMAP.md)의 106~129번입니다.
v0.9.6 태그 릴리스, npm provenance, GitHub Release, canonical·backup Pages와 공개
산출물 parity는 실제 실행으로 확인했습니다. 이는 iPhone·Android·실기기 스크린리더,
외부 프로젝트 사례 또는 향후 deprecated migration·FLIP 수요 증거를 대신하지 않습니다.
