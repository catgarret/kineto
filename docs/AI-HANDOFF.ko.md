# Kineto AI 인수인계 사용 안내

AI에게 전달할 정본은 영문
[`AI-HANDOFF.md`](AI-HANDOFF.md)입니다. 이 문서는 소유자와 한국어
사용자가 영문 정본의 목적과 사용법을 확인하기 위한 안내입니다.
다른 언어용 AI도 별도 번역본 대신 영문 정본을 사용합니다.

## 새 AI 작업을 시작할 때

저장소 전체를 전달할 수 있다면 아래 한 문장과 함께
`docs/AI-HANDOFF.md`를 먼저 읽게 합니다.

> `AGENTS.md`와 `docs/AI-HANDOFF.md`를 순서대로 읽고, 채팅 요약을
> 그대로 믿지 말고 현재 Git diff·계약·테스트로 상태를 다시 검증해줘.

AI는 채팅을 프로젝트 기록으로 사용하면 안 됩니다. 공개 API와
소유자 의도는 `kineto.features.json`, `kineto.requirements.json`,
`OWNER_REQUIREMENTS.md`가 잠그고, 실제 변경 이력은 Git과
`CHANGELOG.md`가 남깁니다.

## 작업 중 확인할 원칙

1. 기존 공개 API와 동작의 하위 호환성을 우선합니다.
2. 테스트를 통과시키려고 기능·옵션·데모를 삭제하지 않습니다.
3. 모듈 연동은 실제 사용 가치가 분명한 조합만 추가합니다.
4. 순환 의존성, 범용 이벤트 버스, 큰 번들 증가가 생기면 구현하지
   않고 후보와 이유를 문서에 남깁니다.
5. 패치 릴리스 직전에는 패키지 exports나 모듈별 엔트리를 바꾸지
   않습니다.
6. 파일 삭제·통폐합은 저장소 전체 참조를 확인한 뒤 진행합니다.
7. 소스·데모·설정·문서·번역·계약·테스트를 한 작업으로 맞춥니다.
8. 커밋 전 `npm run ci`, 배포 전 `npm run verify`를 실행합니다.

## AI가 Git을 사용할 수 없을 때

마지막 답변에 사용자가 그대로 붙여넣을 수 있는 명령이 있어야 합니다.
명령에는 실제 저장소 경로, 검증 명령, 정확한 변경 파일, 실제 커밋
메시지가 들어가야 합니다. `<changed-files>` 같은 placeholder는
허용하지 않습니다.

검증·커밋 명령과 배포 명령은 분리합니다. 소유자가 배포를 승인하기
전에는 tag, push, npm publish, GitHub Release 명령을 실행하거나
자동 실행 블록에 섞지 않습니다.

## 완료 보고에서 확인할 내용

- 완료·부분 완료·보류 항목
- 수정·추가·삭제 파일
- 주요 diff
- 실행한 테스트와 결과
- 빌드·번들·패키지 크기
- 하위 호환성 위험
- 권장 버전과 근거
- 영문 다음 한글 순서의 릴리스 노트
- 검증·커밋·배포용 복붙 명령

AI가 “완료”라고 말한 내용도 실제 테스트 결과와 Git diff가 없으면
완료로 보지 않습니다.
