# @dong-gri/kineto-mcp

MCP (Model Context Protocol) server for [Kineto](https://kineto.dongri.me). It lets a coding agent — Claude Code, Cursor, Codex, Claude Desktop, or a Figma MCP flow — pick, configure and validate Kineto motion modules from the **real feature contract** instead of guessing attribute names.

Everything is answered from contract copies bundled at build time (`kineto.features.json`, `kineto.integrations.json`, module metadata and the AI rules). The server runs over stdio only: no ports, no network, no file access outside the package.

## Install into your agent

```bash
npx @dong-gri/kineto-mcp   # runs the stdio server
```

**Claude Code**

```bash
claude mcp add kineto -- npx -y @dong-gri/kineto-mcp
```

**Cursor** (`.cursor/mcp.json`) / **Claude Desktop** (`claude_desktop_config.json`) / **Codex** (`~/.codex/config.toml`, `[mcp_servers.kineto]`)

```json
{ "mcpServers": { "kineto": { "command": "npx", "args": ["-y", "@dong-gri/kineto-mcp"] } } }
```

## Tools

| Tool | Ask it for |
|---|---|
| `kineto_suggest` | Rank design intents for a description, component or Figma layer name (English or Korean) → recipes with ready `data-kt-*` attributes and snippets. Pass `ecosystem` (shadcn, bootstrap, mui, …) to learn whether the library already provides the behaviour. |
| `kineto_figma_layers` | Map a list of Figma layers (name + type/fontSize/imageFill/text from the Figma MCP) to intents and attributes in one call. |
| `kineto_snippet` | Exact markup for module + variant + options in `html`, `react`, `vue` or `js` form, validated first. |
| `kineto_validate_options` | Check an options object: unknown keys with "did you mean", variant hints, attribute spellings. |
| `kineto_module` | Full public contract of one module (variants, options, defaults, JS API, snippets). |
| `kineto_list_modules` | Every module with attribute, variants, accessibility/performance/reduced-motion status and the intents that use it. |
| `kineto_ecosystem` | How to attach Kineto next to shadcn/ui, Tailwind, Bootstrap 5, MUI, Mantine, Chakra, Ant Design, daisyUI, Nuxt UI, PrimeVue or Vuetify: setup, what the library provides, conflicts, per-intent decisions, examples. |

Resources: `kineto://rules` (agent rules, Markdown), `kineto://integrations`, `kineto://features`, `kineto://meta`. Prompt: `kineto_apply_motion`.

## Typical flow

1. `kineto_ecosystem("shadcn")` — learn the attach pattern and conflicts.
2. `kineto_suggest("hero headline", ecosystem: "shadcn", framework: "react")` or `kineto_figma_layers([...])`.
3. `kineto_snippet("textReveal", variant: "hangul", options: { speed: 30 }, framework: "react")`.
4. Add `<KinetoProvider>` (from the shadcn registry `@kineto/provider`) or call `Kineto.observe()` once.

## Development

The contract copies under `contracts/` and `src/lib.mjs` are generated by `scripts/build-mcp.mjs` in the Kineto repository (`npm run integrations:build`); `tests/integrations-contract.mjs` fails when they drift. `npm test` spawns the binary over stdio and exercises every tool, resource and prompt.

Versioning: this package has its own version; `kineto://meta` reports the Kineto version it was generated from.

Releases: bump the version, add a `CHANGELOG.md` section and a bilingual note under `.github/release-notes/mcp-vX.Y.Z.md`, then `npm run release:ship -- mcp-vX.Y.Z` from the repository root (owner approval required). `.github/workflows/release-mcp.yml` verifies the tag and publishes with npm provenance; see `docs/RELEASING.md` for the one-time Trusted Publishing bootstrap.
